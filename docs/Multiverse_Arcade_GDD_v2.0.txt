	1. Visi Produk dan Pilar
Multiverse Arcade adalah satu aplikasi "hub" berisi lima game 3D berbeda. Pemain bebas memilih game, berpindah kapan saja, dan setiap game punya identitas sendiri di bawah satu sistem navigasi, audio, pengaturan, dan penyimpanan yang seragam.
Pilar produk
1. Modular: tiap game bisa dikembangkan, dites, dan dibuang/diganti tanpa merusak game lain.
2. Konsisten di lapisan global: menu, pause, pengaturan, audio, dan loading terasa sama di semua game.
3. Beragam di lapisan gameplay: genre dan mekanisme inti tiap game berbeda jelas.
4. Stabil: tidak ada crash saat pindah game berulang kali (stress test 50x switch).
5. Realistis: MVP dulu, fitur lanjutan masuk backlog berprioritas.
Target pengalaman: dari buka aplikasi sampai bermain maksimal 3 klik; pindah game maksimal 5 detik loading di laptop target.

	2.3 State Machine Aplikasi
Boot → MainMenu → GameSelection → Loading → InGame ⇄ Paused → (Result) → GameSelection/MainMenu → Quit
Aturan transisi:
* Setiap transisi keluar dari InGame wajib memanggil IArcadeGame.OnGameExit() lalu Time.timeScale = 1.
* Paused hanya valid dari InGame. Pause menyetel timeScale = 0 dan menjeda audio SFX.
* Loading selalu lewat SceneLoader; tidak ada pemanggilan SceneManager.LoadScene langsung dari game.
2.4 Event Bus (komunikasi longgar)
Event global (contoh): OnGameStarted(gameId), OnGamePaused, OnGameResumed, OnGameEnded(gameId, result), OnSceneLoadRequested(sceneName), OnSettingsChanged. Game menerbitkan event, manager global mendengarkan. Tujuannya: game tidak perlu tahu cara kerja manager.

2.5.1 Kontrak IArcadeGame
Setiap game memiliki satu komponen "GameEntry" yang mengimplementasikan:
public interface IArcadeGame
{
   string GameId { get; }
   void OnGameEnter();   // dipanggil saat scene siap
   void OnGamePause();
   void OnGameResume();
   void OnGameRestart(); // reset penuh state game
   void OnGameExit();    // bersihkan event, coroutine, audio
}
GameManager memanggil kontrak ini; game tetap bebas mengatur logika internalnya.
2.6 Penyimpanan
Data minimum: volume, kualitas grafis, lastPlayedGameId, high score per game. Format JSON versi 1 dengan field version agar bisa migrasi. Game menyimpan skor lewat SaveManager.SetHighScore(gameId, value), bukan PlayerPrefs langsung.
2.7 Input
Pilih satu sistem untuk seluruh project (Input Manager lama atau Input System). Rekomendasi: Input Manager lama untuk kemudahan tim pemula; semua game memakai Esc = Pause. Jika ada game yang butuh Input System, harus disepakati bersama dan dikonfigurasi di Project Settings.

	3.3 Layer, Tag, dan Collision Matrix (bagian global)
Layer global dicadangkan agar tidak bentrok: Default, UI, Ground, Walls. Setiap anggota memakai layer game-nya sendiri dengan prefiks (mis. Syafiq_Player) atau menggunakan tag. Catatan: Unity hanya mendukung 32 layer; sepakati kuota per anggota (maks. 4 layer custom per game) di awal.
3.4 Assembly Definition
Tiap game punya asmdef sendiri (MultiverseArcade.Syafiq, dst.) yang merujuk MultiverseArcade.Core. Manfaat: compile lebih cepat dan ketergantungan antar-game terlarang secara teknis.

5.5 Stat Dasar dan Rumus
* TTK (time to kill) target tengah: HP 100 / 20 dmg = 5 tembakan x 0,4 s = ±2,0 s jika semua kena.
* Hit rate realistis 50% → TTK ±4 s, cukup untuk 3 menit pertandingan.
* Kecepatan proyektil 14 u/s, jangkauan 10 u, masa hidup 0,8 s.
* Super charge: +10% per damage 20 diberikan, +25% per eliminasi; super siap pada 100%.
5.6 Sistem Combat
Alur damage (data flow)
1. PlayerCombat/BotAI meminta proyektil dari ProjectilePool (object pooling).
2. Proyektil diberi ownerTeamId, damage, speed, lifetime.
3. OnTriggerEnter → cek layer → Health.TakeDamage(damage, attackerTeamId, attacker).
4. Health menolak damage jika teamId sama atau karakter sudah mati/invulnerable.
5. Jika currentHealth <= 0 → Die() sekali saja → event OnCharacterDied(victim, killer).
6. ArenaMatchManager mendengar event, menambah skor tim, memberi super charge, memicu respawn atau cek akhir pertandingan.

5.8 Desain Arena
* Ukuran awal 30 x 30 u, simetris sumbu tengah agar adil bagi kedua tim.
* Zona: Blue Spawn (barat daya), Red Spawn (timur laut), Central Zone dengan 4–6 obstacle sebagai cover.
* Tiga lane (kiri, tengah, kanan) agar bot punya pilihan jalur.
* Dinding batas tinggi 2 u dengan collider tebal agar proyektil tidak tembus.
* Navmesh: bake dengan Agent Radius sesuai kapsul karakter (±0,5) dan Step Height rendah; obstacle bergerak memakai NavMeshObstacle (carve).
* Iterasi: arena kedua (variasi tema) sebagai stretch goal.

5.12 Animasi, VFX, dan Audio
Animator: layer Locomotion (Idle, Run, Strafe via blend tree dengan parameter Speed, MoveX, MoveZ), layer UpperBody (Shoot, Hit, Skill), state Death. Karakter menghadap arah bidik sementara kaki mengikuti arah gerak (upper-body aiming).
VFX: muzzle flash, trail proyektil, impact spark, dash trail, efek eliminasi (poof), indikator spawn. Gunakan Particle System/VFX Graph ringan; maksimum 200 partikel aktif.
Audio: SFX tembak, hit, eliminasi, skill, countdown, pause, win/lose; musik loop ringan. Semua via AudioManager dengan mixer group SFX/Music.

5.14 State Pertandingan
Countdown → Playing → (Paused) → Finished → ResultShown
Pada transisi ke Finished: nonaktifkan input, hentikan timer, hentikan bot (NavMeshAgent.isStopped = true), tampilkan Result Panel. Pada Restart: bersihkan proyektil di pool, reset HP, posisi, skor, timer, status effect, cooldown, dan Time.timeScale = 1.

5.17 Performa
* Object pooling untuk proyektil (pool 60) dan efek.
* Pencarian target berkala (0,3–0,5 s) dengan Physics.OverlapSphereNonAlloc.
* NavMeshAgent.SetDestination maksimum 5–10x per detik per bot.
* Hindari Find/GetComponent di Update; cache referensi.
* Gunakan Time.deltaTime untuk semua gerak; fisika di FixedUpdate.

	11. Glosarium
* MVP: versi paling sederhana yang sudah bisa dimainkan.
* FSM: Finite State Machine, model perilaku berbasis state.
* ScriptableObject: aset data Unity untuk menyimpan konfigurasi.
* Object Pooling: memakai ulang objek agar tidak sering Instantiate/Destroy.
* NavMesh: mesh navigasi untuk pathfinding AI.
* TTK: Time To Kill, waktu untuk mengalahkan target.
* DoD: Definition of Done, kriteria sebuah pekerjaan dianggap selesai.
* Greybox: prototype kasar tanpa aset visual final.
